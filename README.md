# CHE1147 Group 6 — Predicting Tox21 Stress-Response Activity

Machine-learning classification and molecular-descriptor interpretation for five Tox21 stress-response assays.

**Course:** CHE1147 — Chemical Data Science and Engineering, University of Toronto (Fall 2026)  
**Team:** Natasha Sia, Weikun Liao, and Brandon Hermalin  
**Repository:** https://github.com/Natashasia/CHE1147-Group-6

## Research question

**How accurately can molecular descriptors predict activity across five Tox21 stress-response assays, and to what extent are the most influential descriptors shared across assays?**

We train assay-specific binary classifiers to predict whether a molecule is *active* (1) or *inactive* (0), compare predictive performance, and examine the consistency of influential RDKit descriptors across assays.

The five endpoints are SR-ARE, SR-ATAD5, SR-HSE, SR-MMP, and SR-p53.

## Data

- **Source:** [Tox21 Data Challenge (2014)](https://tripod.nih.gov/tox21/challenge/data.jsp), stress-response panel.
- **Input format:** SDF chemical structures and available assay labels.
- **Molecular representation:** Canonical isomeric SMILES and 217 RDKit physicochemical, topological, and fragment descriptors per unique molecule (before model-specific screening).
- **Deduplication and label consolidation:** Molecular structures are canonicalized, and one structural row is retained per unique molecule. Available assay labels across duplicate records are merged by **majority vote**; ties are assigned `NaN`. This reduces 11,761 source records to 8,041 unique molecules and recovers 5,460 assay labels that would be missing under a keep-first policy.
- **Missing labels:** Missing or unresolved assay labels are preserved in the cleaned dataset and excluded **separately for each assay** during training. Missing labels are never assumed inactive.

The processed data are generated by the EDA notebook; they are not manually feature-selected before splitting.

## Analysis workflow

The final analysis is organized into three sequential Jupyter notebooks:

| Notebook | Purpose | Main operations |
| --- | --- | --- |

| `03_Results_Interpretation.ipynb` | Interpretability and cross-assay comparisons | Standardized LR coefficients, RF permutation importance, **supplementary RF SHAP**, top-10 descriptor rankings, Jaccard similarity and descriptor-sharing summaries |

### Modeling and evaluation

- **Baseline:** `DummyClassifier(strategy="prior")`, providing an assay-specific no-skill reference.
- **Logistic Regression (LR):** Training-fold descriptor screening and removal of strongly correlated features (absolute Pearson correlation > 0.90), followed by sequential forward selection (SFS). SFS selects at most 30 descriptors and stops when incremental mean CV AP improvement falls below 0.001. A grid search tunes regularization strength and class weighting (12 combinations).
- **Random Forest (RF):** Training-fold descriptor screening without correlation filtering. `RandomizedSearchCV` evaluates **100 randomly sampled configurations per assay** from a space of 864 possibilities; individual forests use `n_jobs=1` to avoid nested parallelism.
- **Splitting:** Approximately 80/20 assay-specific train/test partitions and five-fold scaffold-aware stratified CV within training data. Groups use Bemis–Murcko scaffolds, with canonical SMILES as the fallback for acyclic molecules. Groups remain disjoint between partitions. The CV fold-selection procedure requires both activity classes in every fold, zero scaffold overlap, validation sizes between **50% and 170%** of the expected fold size, and validation positive-class prevalence within **±5 percentage points** of the training-set prevalence. It tries an unshuffled split first, then randomized seeds if needed.
- **Primary selection metric:** Average Precision (AP), appropriate for the imbalanced activity labels. Additional metrics include ROC-AUC, trapezoidal PR-AUC, precision, recall, F1 and accuracy.
- **Binary predictions:** A fixed 0.5 decision threshold is used for the reported confusion matrices. AP and ROC-AUC are based on prediction scores across thresholds.

Descriptor screening and SFS occur inside the training/CV workflow to avoid validation leakage. Hyperparameters are selected without optimizing on the final held-out test set.

### Interpretation

1. **Primary RF importance:** Rank descriptors by the mean decrease in held-out test AP when each descriptor is independently permuted ten times.
2. **Supporting LR importance:** Rank SFS-selected descriptors by absolute standardized coefficient magnitude, retaining coefficient signs.
3. **Supplementary RF SHAP:** Use TreeExplainer on each assay's held-out test set to calculate mean absolute SHAP values, descriptor–SHAP correlations and beeswarm plots. SHAP shows prediction-level contributions and their direction; it **does not replace permutation importance** in the primary descriptor rankings.
4. **Across assays:** Compare permutation-based RF and coefficient-based LR top-10 descriptor sets separately using pairwise Jaccard similarity (10 assay pairs for each model), descriptor occurrence tables and sharing summaries.
5. **Across models:** Compare LR and RF top-10 sets within each assay using Jaccard similarity.

LR coefficients, RF permutation importance and SHAP values measure different aspects of importance and are not directly comparable in magnitude. Correlated descriptors may distribute importance across related features. SHAP beeswarm colours indicate descriptor values; the direction of SHAP contributions describes model behaviour, **not causal chemical effects**. SHAP rankings are supplementary and are not used in the cross-assay Jaccard calculations.

- Git
- Python and [uv](https://docs.astral.sh/uv/) (uv can manage the required Python version)

```bash
git clone https://github.com/Natashasia/CHE1147-Group-6.git
cd CHE1147-Group-6
```

This repository includes `pyproject.toml` and `uv.lock`. After confirming that the declared dependencies cover the imports used by the final notebooks, run:

```bash
uv sync --locked
```

The `--locked` flag checks that the lockfile is consistent with the project configuration, rather than silently rewriting it. If the command reports missing or inconsistent dependencies, update `pyproject.toml`/`uv.lock` in the project and commit both files together.

For VS Code, choose the repository's `.venv` Python interpreter as the Jupyter kernel.

### 3. Configure VS Code

1. Open the repository folder in VS Code.
2. Ensure the Python and Jupyter extensions are installed.
3. Open any .ipynb notebook.
4. Click Select Kernel and choose the repository's .venv Python environment.

If JupyterLab is installed in the project environment, launch it using:

```bash
uv run jupyter lab
```

## Reproducing the analysis

Run the final notebooks **in the following order** from the cloned repository:

1. **`notebooks/01_EDA.ipynb`** — Place the original SDF in `data/raw/`, then execute all cells. This creates `data/processed/tox21_clean.csv` and EDA outputs.
2. **`notebooks/02_Preprocessing_Models_Evaluation.ipynb`** — Use the full production configuration to train and evaluate the Dummy, LR and RF models. This stage creates split assignments, validation diagnostics, `.joblib` models, test predictions, model metrics and evaluation figures. Full fitting, particularly RF tuning, can be computationally expensive.
3. **`notebooks/03_Results_Interpretation.ipynb`** — Load the cleaned data and saved models/results, verify recorded test predictions, and generate LR/RF feature importance, Jaccard and shared-descriptor outputs, plus supplementary RF SHAP importance tables and beeswarm figures for all five assays. This stage does **not** retrain the classification models.

**Important:** Keep the cleaned dataset, split assignments, saved model files, and evaluation outputs from the **same Notebook 02 run**. Model and preprocessing artifacts may not be compatible across different package versions.

## Reproducibility and limitations

- The current notebooks set a base random seed of `42`. Record the actual selected holdout and CV seeds (deterministic CV may record no seed), together with fold diagnostics and split assignments.
- Notebook 02's current `run_manifest.json` code records the complete RF search space of 864 configurations but **does not yet explicitly save `RandomizedSearchCV(n_iter=100)`** or the customized CV acceptance thresholds. The actual RF CV results show the sampled configurations. To improve provenance, add those fields to the manifest before the next full run.
- Keep all output files from one coherent run of the majority-voted dataset; mixing model artifacts and CSVs from earlier keep-first runs will invalidate comparisons.
- Missing or ambiguous assay labels, rare positive classes, scaffold shifts, and limited scaffold diversity within some CV folds may affect generalization estimates.
- The default 0.5 binary prediction threshold is not optimized for safety-critical screening; it may yield low recall for rare active compounds. Use AP rather than trapezoidal PR-AUC for comparisons with the constant-score Dummy baseline.
- Correlated descriptors can obscure individual RF permutation importance and complicate SHAP attribution. SHAP and permutation rankings need not agree. Feature importance and overlap describe model associations, **not causal effects** or statistically established common biological mechanisms.
- Document modifications made after the saved model run and keep the project dependency lockfile consistent with the notebooks, including SHAP.
