# CHE1147 Group 6 — Predicting Tox21 Stress-Response Activity

Machine-learning classification and molecular-descriptor interpretation for five Tox21 stress-response assays.

**Course:** CHE1147 — Chemical Data Science and Engineering, University of Toronto (Fall 2026)  
**Team:** Natasha Sia, Weikun Liao, and Brandon Hermalin  
**Repository:** https://github.com/Natashasia/CHE1147-Group-6

## Research question

**To what extent are the most influential molecular descriptors shared across the five Tox21 stress-response assays?**

We train assay-specific binary classifiers to predict whether a molecule is *active* (1) or *inactive* (0), compare predictive performance, and examine the consistency of influential RDKit descriptors across assays.

The five endpoints are SR-ARE, SR-ATAD5, SR-HSE, SR-MMP, and SR-p53.

## Data

- **Source:** [Tox21 Data Challenge (2014)](https://tripod.nih.gov/tox21/challenge/data.jsp), stress-response panel.
- **Input format:** SDF chemical structures and available assay labels.
- **Molecular representation:** Canonical SMILES and RDKit physicochemical, topological, and fragment descriptors (approximately 217 descriptors before modeling-specific screening).
- **Deduplication:** Invalid or missing canonical SMILES are removed. When a canonical structure occurs more than once, the first record is retained; duplicate assay labels are not merged.
- **Missing labels:** Preserved in the cleaned dataset, then excluded separately for each assay** during model training. Missing labels are not assumed inactive.

The processed data are generated by the EDA notebook; they are not manually feature-selected before splitting.

## Analysis workflow

The final analysis is organized into three sequential Jupyter notebooks:

| Notebook | Purpose | Main operations |
| --- | --- | --- |
| `01_EDA.ipynb` | Exploratory data analysis and dataset preparation | SDF conversion, structure cleaning, label balance and co-occurrence, descriptor quality and correlations, processed-data export |
| `02_Preprocessing_Models_Evaluation.ipynb` | Model development and evaluation | Scaffold-aware splitting, fold-specific preprocessing, Dummy/LR/RF training, hyperparameter searches, saved predictions and models |
| `03_Results_Interpretation.ipynb` | Interpretability and cross-assay comparisons | Standardized LR coefficients, RF permutation importance, top-10 descriptors, Jaccard similarities, descriptor-frequency and overlap summaries |

### Modeling and evaluation

- **Baseline:** `DummyClassifier(strategy="prior")`, providing an assay-specific no-skill reference.
- **Logistic Regression (LR):** Training-fold descriptor screening; remove highly correlated features (absolute Pearson correlation > 0.90); sequential forward selection (SFS), with a maximum of 30 selected features and minimum mean CV AP improvement of 0.001 in the latest run. Model regularization and class weights are selected by grid search.
- **Random Forest (RF):** Training-fold descriptor screening without LR's correlation filter. The latest saved run sampled 100 parameter combinations per assay using `RandomizedSearchCV` from the declared RF search space.
- **Splitting:** Assay-specific held-out test sets and five-fold, scaffold-aware training cross-validation, using Bemis–Murcko-based groups. Test scaffolds are excluded from the corresponding training set.
- **Primary selection metric:** Average Precision (AP), appropriate for the imbalanced activity labels. Additional metrics include ROC-AUC, trapezoidal PR-AUC, precision, recall, F1 and accuracy.
- **Binary predictions:** A fixed 0.5 decision threshold is used for the reported confusion matrices. AP and ROC-AUC are based on prediction scores across thresholds.

Descriptor screening and SFS occur inside the training/CV workflow to avoid validation leakage. Hyperparameters are selected without optimizing on the final held-out test set.

### Interpretation

1. **Primary analysis (RF):** Compute repeated permutation importance using the decrease in held-out AP after shuffling one molecular descriptor.
2. **Supporting analysis (LR):** Extract standardized, signed regression coefficients; rank selected descriptors by absolute coefficient magnitude.
3. **Across assays:** Compare each model's top-10 descriptor sets using pairwise Jaccard similarity (10 unique assay pairs), a descriptor-by-assay occurrence table, and summary counts of descriptors found in exactly or at least 1–5 assays.
4. **Across models:** Compare the LR and RF top-10 sets within each assay using Jaccard similarity.

LR coefficients and RF permutation scores have different meanings and units; their descriptor identities, not raw importance values, are compared across models. Shared predictive descriptors do not establish shared causal biological mechanisms.

## Installation and environment reproduction

### Prerequisites

- Git
- Python and [uv](https://docs.astral.sh/uv/) (uv can manage the required Python version)
- A Jupyter-capable editor such as VS Code or JupyterLab

### 1. Clone the repository

```bash
git clone https://github.com/Natashasia/CHE1147-Group-6.git
cd CHE1147-Group-6
```

### 2. Recreate the Python environment

This repository includes `pyproject.toml` and `uv.lock`. After confirming that the declared dependencies cover the imports used by the final notebooks, run:

```bash
uv sync --locked
```

The `--locked` flag checks that the lockfile is consistent with the project configuration, rather than silently rewriting it. If the command reports missing or inconsistent dependencies, update `pyproject.toml`/`uv.lock` in the project and commit both files together.

For VS Code, choose the repository's `.venv` Python interpreter as the Jupyter kernel.

### 3. Configure VS Code

1. Open the repository folder in VS Code.
2. Ensure the Python and Jupyter extensions are installed.
3. Open any .ipynb notebook.
4. Click Select Kernel and choose the repository's .venv Python environment.

### Optional: Using JupyterLab

If JupyterLab is installed in the project environment, launch it using:

```bash
uv run jupyter lab
```

JupyterLab is optional and is not required when using VS Code.


## Reproducing the analysis

Run the final notebooks **in the following order** from the cloned repository:

1. **`notebooks/01_EDA.ipynb`** — Place the original SDF in `data/raw/`, then execute all cells. This creates `data/processed/tox21_clean.csv` and EDA outputs.
2. **`notebooks/02_Preprocessing_Models_Evaluation.ipynb`** — Use the full production configuration to train and evaluate the Dummy, LR and RF models. This stage creates split assignments, validation diagnostics, `.joblib` models, test predictions, model metrics and evaluation figures. Full fitting, particularly RF tuning, can be computationally expensive.
3. **`notebooks/03_Results_Interpretation.ipynb`** — Load the cleaned data and saved models/results, verify the recorded test predictions, and generate feature-importance, Jaccard and shared-descriptor outputs. This stage does **not** retrain the classification models.

**Important:** Keep the cleaned dataset, split assignments, saved model files, and evaluation outputs from the **same Notebook 02 run**. Model and preprocessing artifacts may not be compatible across different package versions.

## Reproducibility and limitations

- Set and document random seeds (latest run: `42`). Scaffold-aware partitions and CV folds are recorded in the exported diagnostic files.
- Review `run_manifest.json`, the actual `cv_results_*.csv`, and the executable notebook together. The supplied run manifest lists the complete 864-combination RF search space, while the saved RF CV results show 100 sampled configurations per assay. Update the manifest to explicitly record `RandomizedSearchCV(n_iter=100)` for complete provenance.
- Missing assay labels, small positive classes, and scaffold shifts can affect test performance and precision-recall metrics.
- The default 0.5 decision threshold may have low recall for rare active molecules; it is not optimized for safety-critical screening.
- Permutation importance may distribute importance across correlated descriptors. Importance rankings and their overlap are descriptive measures of model dependence, not demonstrations of causality or statistically significant common mechanisms.
- The final report should document any modifications made after the saved run.
